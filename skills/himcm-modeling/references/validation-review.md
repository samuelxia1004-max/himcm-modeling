# 验证、队内评审与修复

【官方经验】评委重视有依据的假设、合理应用、连贯模型、敏感性分析及可执行建议；敏感性方法需说明参数、范围、测试方式、输出和实际含义。[`https://www.contest.comap.org/highschool/contests/himcm/flyers/Cons_HiMCM.pdf` 第 5 至 12 页] 以下评价器、证书和两轮评审是本地工作方法。

## 1. 先写正式评价口径

程序优化前，明确同一候选如何获得正式结果：

| 项目 | 必须固定的内容 |
|---|---|
| 输入 | 数据版本、单位、缺失处理、场景及可用信息 |
| 输出 | 目标值、逐条可行性、风险或误差及诊断量 |
| 比较 | 优化方向、并列处理、多个目标的优先级或权重 |
| 精度 | 时间步长、网格、求解精度、取整和容差依据 |
| 复算 | 输入路径、命令、代码版本、配置及随机设置 |

先判定约束，再比较合法候选的目标。加权惩罚可能使低成本但违规的方案占优，因此最终输出应列出每条硬约束检查。近似评分可帮助筛选；正式排名和论文结果使用统一评价口径。评价公式、输入或约束变化时，相关结果需重新计算。

评价器应通过手算小例、量纲、边界、非法输入和独立复算。独立复算要改变一种错误传播路径，例如另一条公式、手算、解析不变量、精确小规模枚举或独立实现。同一评价器上两个算法输出接近，只能支持重复一致性。

基线比较还要核对双方可用信息、预处理、情景/样本、调参及计算预算、停止条件和约束。随机方案可在相同情景上比较成对差值，记录配对单位；这提高比较公平性，不能替代评价器的独立核验。多模块方法若声称某模块带来收益，选择能隔离该贡献的合理简化对照，保留题面硬约束。效率声明说明计时范围、环境和实际开销。

记录基线实现来自本队代码、原作者公开实现还是软件包，绑定版本或文件哈希。模型假设、实现适配和正式评价口径分别可回查。

模型合同、资格/评分分层、完整服务时间链和共同样本交叉比较见 [decision-contracts.md](decision-contracts.md)。涉及化简、并列解、唯一性或必要性时，检查原可行域中被排除的一个合法边界例；保留主目标的化简不自动保留二级目标或风险。受限搜索的失败只针对明确的搜索族，除非另有完整证明。看到结果后的补充检查与初始验收分别记录。

## 2. 测试应能改变建议

先记录主要风险、测试范围及判定后果，再看结果。下面按风险选用，无须每题全部执行。

| 风险 | 有区分度的测试 | 可能推翻的结论 |
|---|---|---|
| 目标定义错误 | 手算两人同时工作，比较最长时间与时长总和 | 优化目标与“全部完成时间”不一致 |
| 路线约束遗漏 | 一个断开的房间；封闭一条必经边；同一窄通道并发 | 方案不可执行，需要重建约束或重规划 |
| 搜索偏向局部区域 | 小例枚举；从不同结构起步；检查剪枝删去区域 | 当前最优候选受表示或筛选限制 |
| 排名依赖权重 | 在有依据的权重范围内变化，记录名次翻转边界 | 单一城市建议应改为条件化选择 |
| 标准化影响排名 | 合理尺度变换；加入无竞争力候选后重算 | 排名依赖参照集合或尺度 |
| 数据年份/缺失偏差 | 同口径年份比较；替代缺失处理；未来情景 | 跨城或跨年比较缺乏可比性 |
| 预测泄漏 | 按时间留出，预处理只用历史训练段 | 原准确度高估，模型选择需重做 |
| 仿真极端风险 | 合理的低速、堵塞、长服务时间组合 | 平均表现不足以支持安全建议 |

参数范围优先来自题面、领域来源或测量误差；探索性范围写明理由。除单参数变化，还应在关键参数可能共同变化时做组合情景。记录所有已尝试检查及失败原因。

涉及统计推断时，先定义独立单位、配对或群组关系、时间/空间依赖及所估计的量。同一对象的多时刻、重复折次和随机运行次数不能自动当作独立样本数。检验、重采样与区间方法应保留依赖结构；报告实际单位数、效果差、区间含义及必要的多重比较处理。分别命名估计区间、未来预测区间、模拟波动与无概率解释的情景范围。比较成对差异时，直接评估差值的不确定性；两组边际误差条是否重叠不能代替该比较。

若比较改进幅度，可用 `(基准值 − 模型值) / 基准值` 表示成本下降比例；基准为零时另报绝对差。随机输出的波动与模型假设的不确定性分别讨论。均值稳定但关键排名反转，说明决策仍不稳。建议应写清成立范围、切换条件及备用方案。

## 3. 冻结结果与声明强度

每问建立轻量结果记录，绑定题意约定、正式评价器、代码/输入/配置、原始输出、单位与精度、可行性、已执行验证、剩余风险和可写进论文的事实。用相对路径和文件版本或哈希回查。图、表、摘要读取这份记录。

| 证据 | 合适表达 |
|---|---|
| 严格证明，或适用模型下求解器证明最优且容差已说明 | “在该模型下达到最优” |
| 只有可证明上下界 | 报告界及尚余差距 |
| 有限预算搜索得到合法候选 | “在所述搜索预算下得到的最佳可行方案” |
| 固定策略的确定性复算 | “该策略在此情景下的结果” |

定理和算法性质需核对当前表示、前提和证据。加权替代、时间离散或松弛会改变问题，原模型性质应重新检查。正式搜索按预算、收敛或预设无提升条件停止；复评后进入结果核验。

## 4. 两轮队内评审

【本地建议】两轮用于检查和修复，不模拟获奖结果。2025 年官方说明每篇先由至少两名初审评委评阅，部分论文进入终评；本地轮次与官方评审制度分别记录。[2025 评述第 2 页]

第一轮读完整题面、模型、数据、代码和当前稿，集中找正确性问题。逐问追踪：要求是否完成，假设是否用于公式，约束是否遗漏，数据是否可信，基准是否公平，评价器是否独立验证，建议是否经得起反证。每个问题写清位置、证据、影响、负责环节、最小修复和复查方法。

问题表保留稳定编号、主张位置、证据位置和阻塞性；后续轮次沿用编号。阻塞项以其是否妨碍核心解答或建议成立判断，修复条件写成可观察的复验结果。核查代理指标、推断单位、竞争解释、比较预算和因果声明的支撑。多个独立审阅者先读取同一冻结材料、形成各自意见，再综合；记录实际独立性与阅读范围。

数学错误回到建模或求解；数值证据缺口补运行或复算；引用和解释问题修论文；页数、匿名和图表问题修版式。修改后只重跑受影响链，更新结果、图表、正文和摘要。保留问题表及解决证据。

第二轮读取修订后的完整稿和实际 PDF，从读者角度重新核查所有题目要求、首轮阻塞项、摘要与正文一致性、建议的实施条件、英文术语和图表、匿名、页数及 AI 披露。若具备独立审阅条件，提供题面、当前稿和冻结证据，让审阅者先作判断；单人复查时记录审阅范围和独立性。完成标准是阻塞项有证据解决，尚未核验项有明确状态。

可用本地诊断表标记“已支持／待证据／需修复”：任务覆盖、假设、模型理由、实现、验证、连贯性、摘要、非技术文本、图表和引用。每格附证据位置和下一步。这些状态不对应官方权重、分数或奖项预测。

## 5. 收口复查

从原始输入做一次适当范围的干净复算，核对冻结数值和论文取整。代码简化保留数学核心，比较前后正式结果、约束、关键中间量和运行行为。每次代码或结果变化后重验受影响内容。

最终检查实际要提交的 PDF 全页：公式、字体、英文标签、图表大小、页眉、裁切和分页。静态脚本与成功编译各支持其检查范围；视觉通过须来自实际页面检查。匿名复核涵盖可见内容和文件元数据。HiMCM 提交单个英文 PDF；内部复现文件按官方要求保留在本地。[`rules_2026.txt` VI“Preparing a Solution Document”“Submitting a Solution Document”]
