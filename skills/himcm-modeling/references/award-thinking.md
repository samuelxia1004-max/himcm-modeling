# 从题面独立生成可检验的 HiMCM 路线

本流程依据已保存的 95 份 O/F 四类完整报告阅读记录，以及本次对 31 份代表报告的正文选页复核。它把获奖论文中能观察到的建模决定转成新题可执行的流程。具体证据、反例和来源见 [award-common-traits.md](award-common-traits.md)。新题先完成步骤 1–4 并保存独立构思稿，再查相似题例文。

这里采用三个证据标签：**E** 是报告或官方评论中明确写出的内容；**I** 是阅读者据此提出的迁移方法；**U** 是成文报告无法确定的真实思考过程。下述工作流属于 I。论文里的“先分析、再建模”只是发表后的呈现顺序；实际先想到什么、淘汰过哪些路线、如何讨论属于 U。

## 1. 把题面转成决策合同

逐条阅读题面和附件，建立 `requirements.csv`：

```text
requirement_id,对象与范围,决策者,已知输入,可控制动作,必须输出,成功指标,硬约束,验收方法,论文位置
```

给每个输出写操作定义、单位、时间/空间边界。例如“银行平均等待少于两分钟”写成所有顾客等待时间的均值；另记录超时比例用于解释服务风险。“建筑清空”先确定是否包含每个房间确认、救助运输和最后一名响应者退出，再选择最大完成时间及其分位数。必须区分平均、最差个体、总量与概率。出现歧义时列出两种解释及其对动作的影响，并选有题面依据的解释。

先列一个现实中能实施的朴素动作作为基线：固定时段采购、最近点服务、均匀分配、现行规则、保持政策、按题面规定的初始系统运行。基线也必须接受同一个评价器。

## 2. 用表示揭示结构

画一张数量依赖图：外部输入 → 状态/关系 → 可控制动作 → 结果 → 成功指标。优先寻找以下结构，并做一份手算小例：

| 题面结构 | 第一种表示 | 立刻能做的核查 |
|---|---|---|
| 资金、蜂数、车辆、病例、食物随时间变化 | 状态＋流入−流出；必要时分阶段/分工 | 单位、总量、非负、转换是否重复计数 |
| 地点、连接、通行与服务 | 需求点/路网/候选点/覆盖集合 | 不可达点、连接性、最短距离下界、服务对象 |
| 多人/车辆竞争有限资源 | 事件时间线、队列、容量瓶颈 | 无等待极限、饱和容量、先后次序、尾部 |
| 形状、路径、空间铺设 | 坐标、曲线、网格、连续轨迹 | 尺度、坡度、边界、最小间距与可建性 |
| 预测进入后续选择 | 历史信息集、预测窗口、决策库存 | 今天能知道什么、时间划分、误差如何改变行动 |
| 公平、安全、环境等概念需要评价 | 原始指标和方向；偏好单独登记 | 同尺度、边界、重复指标、量表与目标含义 |

先检查守恒、几何、对称、单调性、凸性、可达性和容量。有天然可行的表示时直接使用，例如归一化概率、流量平衡、合法候选路径、单位明确的年度预算。这些结构决定模型空间，随后才选择算法。

## 3. 生成真实不同的候选机制

按题意、结构差异与决策风险形成必要的候选卡，数量由尚未解决的任务和机制分歧决定。单一结构已经足以回答全部要求时，可以保留一个自然模型及检验基线。每张卡写：

```text
路线 ID / 回答的要求 / 表示与状态 / 核心机制 / 可控制动作
假设与理由 / 参数来源及可识别性 / 预计失败场景
与其他路线真正不同的地方 / 最便宜实现 / 区分它们的实验
```

改变下列一项要能产生可解释的结果差异，并明确差异来自何处：

| 构思轴 | 两种可能路线 | 可以区分的实验 |
|---|---|---|
| 聚合尺度 | 总量库存或流率；个体/空间互动 | 同总人数、同总容量，不同空间布局或个体差异 |
| 时间机制 | 静态分配；逐时事件或反馈 | 需求峰谷、库存耗尽、信息到达时刻 |
| 响应机制 | 预先固定动作；遇新信息再规划 | 路径阻断、延迟观测、错误先验 |
| 驱动依据 | 经验预测关系；有边界的机制关系 | 留出期、饱和/零输入、干预超出历史区间 |
| 决策目标 | 平均损失；门槛覆盖/公平/尾部风险 | 少数偏远需求、高峰、极慢个体 |
| 优化耦合 | 所有决策联合；先分区再逐区解 | 小实例精确解、强耦合反例、时间预算 |
| 不确定性 | 标称参数；情景/分布下的行动 | 联合扰动、分布替换、罕见故障 |
| 干预层级 | 改单个参数；重设计系统结构 | 相同预算下培训与增窗口、单纯增站与库存调度 |

所需数据和要回答的干预不同。站台题可比较容量瓶颈解析、位置敏感的元胞/事件模型，以及对安全尾部优化的配置模型。仓库题可比较均匀地面覆盖、订单加权覆盖、忙碌/中断下的服务能力；目标的选择要由题面决定。

给每对候选写一句“在 ___ 情景中，因 ___ 机制，输出 ___ 应当不同”。同一目标、变量、约束和评价器上的 GA、PSO、DE 属于一张模型卡的求解器比较。换工具、加指标或增加参数只有在改变必要机制并带来可检验差异时才形成新的建模路线。

维护一份轻量 `ideation_frontier.csv`，将题面每项要求关联到上表各构思轴；一行对应“要求—构思轴—候选路线”：

```text
requirement_id,构思轴,适用性及理由,候选路线,状态,检验记录,暂缺数据,
省略理由,尚待探索路线,触发条件,预计代价,下一步
```

适用性记“适用/不适用”；状态记“已检验/待检验/暂缺数据/有理由省略”。例如疏散任务的“聚合尺度”适用且已测试等吞吐不同位置；“响应机制”在静态题设下省略，但遇阻断扩展时触发；省略理由要能回到题意、结构风险或预算。每项任务至少连接一条有效路线和验收证据；仍缺关键输入的任务保留条件结论或待解决状态。

## 4. 用便宜的判别实验筛选

建立独立评价器；列清假设、输入、输出、随机机制和停止条件。候选进入大规模计算前按顺序做：

1. **结构检查：** 量纲、守恒、概率和、非负、连接、整数/容量与任务覆盖；检查零输入、无限/零容量、单对象、对称和单位换算。
2. **手算和小规模：** 用精确枚举、解析式或已知下界复算至少一个非平凡小例；独立重算目标与约束。
3. **机制反例：** 选能让候选分歧最大的布局、峰值、阻断或极端个体，检验它们的不同预测。记录被否定的假设和淘汰理由。
4. **数据检验：** 在可获取的训练/调参/测试划分上比较朴素预测、拟合误差和最终决策损失；保留时间顺序或分组。观测不足时用机制边界及明确的条件情景。
5. **数值与随机误差：** 更细时间步/网格、多种子/重复运行、算法预算和可行性；给输出波动及计算误差，判断是否足以分辨方案。

`route_comparison.csv` 至少包含：要求覆盖、可行性、数据缺口、基线差距、判别实验结果、决策稳健性、运行预算、保留/淘汰理由。先修正确性和可实施性，再按题目目标比较。复杂模型要解释解决了哪个已被基线暴露的难点。

每轮实验更新覆盖前沿，把新反例转成候选或触发已有待探索路线。本轮收敛条件是：题面各任务形成可检验的输入—模型—结果—建议闭环；主要结构与决策风险已完成有区分力的检查；剩余计算和数据预算有明确安排。另保留尚待探索路线及触发条件，说明本轮结束的依据。这个记录支持按新证据重开构思，所列路线只表示当前探索范围。

## 5. 组合互补模块，并重新检验接口

模型组合常见三种合理作用：解释性基线核查详细仿真；预测模块为决策模块提供输入；优化给初始方案，情景仿真评价并触发重规划。每条接口记录变量、单位、时间尺度、数据来源、输出分布及复算方法。各模块使用同一任务定义和最终评价器。

加入新状态、评分指标或地域后，重新审核全部受影响输出。通过消融实验说明扩展的贡献：固定其余设置，关掉反馈、空间差异、随机占用或重规划，比较行动与结果。存在强耦合时用小实例联合优化检查分阶段方案的损失。组合的目标是闭合要求和解释核心机制。

## 6. 让验证决定建议

围绕能改变推荐的因素试验：高敏感参数、相互联动、偏好取值、失败场景、外推范围。每项记录“基准—扰动范围/分布—运行次数—评价输出—行动是否翻转”。分别登记：拟合/校准、留出预测、外部观测对照、内部实现核查、参数/结构敏感性、情景分析、决策稳健性、数值误差。

模型间吻合支持内部核查；AHP 一致性支持偏好矩阵的一致程度；随机重复评估 Monte Carlo 误差；输入扰动评估条件响应。用与实际主张匹配的证据支持准确性、稳定性或最优性。优化结果分别表述为固定策略数值、预算内最好、给定模型的上下界/证明最优。

建议写成“谁在什么条件下做什么—预计改善哪项原始指标—相对基线多少—执行资源—关键失效条件”。预算、日期、人数、地点、容量和整数动作要落地复算。报告对近似和数据不足敏感时，优先给条件方案或监测触发规则。冻结论文前检查摘要、表图、正文、建议和结果证书的一致性。
