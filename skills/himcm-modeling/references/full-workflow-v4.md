# HiMCM mathematical modeling

把赛题推进到一份完整、易读、可核验的学生建模报告。以 O/F 作品所呈现的完整性、数学解释、验证和沟通质量为改进目标；奖项取决于当届参赛作品与评审，内部评分不预测奖项。

## 一个技能完成整题

本包包含执行流程、模型选择、数据分析、获奖作品经验、论文与评审规则及机械检查工具。接到完整题面后直接推进到可复现解答和英文报告；外部已安装的数学建模或文风技能只是来源，不是运行依赖。可使用现有计算、检索和文档工具，按真实能力执行并记录缺口。学习文献按需查阅，不把全部文献加载或引用到每道题。

技能承诺的是可执行流程与证据质量；有限文献与测试不能穷尽未来所有合适思路。构思时用覆盖图主动扩大路线空间，用判别测试收敛，交付具体选择、条件与回退。

## 开始与权限

判断任务属于赛前训练、当届比赛、旧题复盘、论文评审还是交付。用户要求完成求解或全权推进时，连续完成已授权的选题、实验、返修和交付，记录路线理由，不逐步请求确认。仅缺少会改变题意的输入、触及实际权限边界或需要人类身份操作时请求必要信息。当前 skill 的创建授权不自动成为未来项目的外部提交授权。

先读取原题与全部官方附件，核对实际工具能力。创建或继续 `PROJECT_CONTEXT.md`，写明剩余时间、当前阶段、输入版本、当前有效结果和下一步。中断后从这些文件恢复。项目输入、结果、引用、图表和文稿的持久化引用采用项目相对路径与 SHA-256。

第一次运行可用：

```bash
python /path/to/himcm-modeling/scripts/init_project.py PROJECT_DIR --year 2026 --problem A
```

## 当届规则优先

读取 [contest-rules.md](contest-rules.md) 和 [contest-profile.json](contest-profile.json)，然后访问当届 COMAP Instructions、题面、AI Policy 与提交公告。保存原文、访问日期和冲突解决理由。包内 2026 快照只提供起点。

已核验的 2026 快照：HiMCM 选 A 或 B；英文 PDF；字号至少 12 pt；摘要为第一页；主报告总计至多 25 页，目录、参考文献、信函和附录计入；AI 使用报告追加在后且不计入 25 页。所有页面有队号与页码，匿名，文件以队号命名且小于 20 MB。实际提交只有一个 PDF，代码与数据留作内部复现。正文使用 AI 的位置和参考文献中也要披露工具、模型及用途。

比赛期间采用现成的非人类资料，遵守禁止队外人类协助、调查访谈和公开传播赛题/方案等规则。检索方法与公开领域知识；避免接触当届题目的他队解答或讨论区。所有 AI 使用记入真实台账并核验。

## 从题面到结果

1. **题意与选题。** 逐条读完题面和附件，保存原始版本；将明示任务和必要上下游关系整理成任务依赖图。把每一条要求转换为“对象、输入、输出、成功标准、约束、验证方法、论文位置”。比较 A/B 的数据可得性、数学可解释性、可完成性、验证机会和团队能力。选择能把全部要求闭环的路线。详见 [problem-to-model.md](problem-to-model.md)。
2. **独立构思。** 先读 [award-thinking.md](award-thinking.md) 的构思流程，使用题意生成本题的结构覆盖图；在读取近题作品或检索整题解答前，保存 `artifacts/independent_ideas.md`。把不同表示、机制和决策层组合成候选，记录各自能回答哪些问、必要数据、公式骨架、判别测试与失败条件。同一模型的 GA/PSO/DE 不算不同模型。先检查守恒、尺度、几何、单调性、凸性、小规模精确解和天然可行参数化。运行小例筛选，选最便宜的有效基线与能闭合全部要求的主线；复杂题的扩展沿同一决策链增加。简单问题允许只有一个自然模型。保存筛选证据、尚未覆盖的路线及采用它们的条件，不以列满模型名称作构思完成标准。某类结构需要展开时读 [model-atlas.md](model-atlas.md)。
3. **数据与研究。** 读 [data-analysis-playbook.md](data-analysis-playbook.md)，按问题选择其中数据路径，执行“原始输入→审计/操作化→探索→处理→拟合或计算→验证→决策→图表/报告”的闭环。保存原始文件，审核单位、时间尺度、缺失、口径、联结和数据泄漏；清洗规则记录实际影响与新分母。题面指定的附件与真实数据任务须实质完成。每个参数标明观测、外部来源、假设、估计或场景；题面允许的虚构人物也须明确标注。无法获得数据时，区分能够支持的条件模型与仍未完成的实证任务，继续检索或收缩结论。建立来源与主张的证据账本。获奖作品的共同表现与反例见 [award-common-traits.md](award-common-traits.md)；23篇标准O/F全文量化所揭示的对象、单位、代码和任务闭环风险见 [award-quantified-audit.md](award-quantified-audit.md)，按本题机制读取；完整 Nature 方法迁移示例见 [nature-method-transfer.md](nature-method-transfer.md)，保留其数据、验证和版本条件。独立构思后按需查 [himcm-corpus-lessons.md](himcm-corpus-lessons.md) 与 [grokbot-corpus-lessons.md](grokbot-corpus-lessons.md)。文献主库为100篇Nature正刊，身份与阅读范围见 [nature-core-index.json](nature-core-index.json)，新增80篇的学习卡见 [nature-core-learning.md](nature-core-learning.md)；原20篇及另外80篇子刊的学习卡见 [literature-learning.md](literature-learning.md)。按模型机制与实际阅读范围检索，将来源模型转成适合本题的可解释结构，重新验证其假设。Grok补充的49篇研究、2篇方法评论及7个相关稿本见 [grok-literature-learning.md](grok-literature-learning.md) 与 [grok-literature-index.json](grok-literature-index.json)，按保存稿本的版本与阅读范围使用。
4. **形式化与求解。** 对核心结果先写验收条件和可能推翻推荐的测试，再固定简短模型合同：输入与信息边界、变量、单位、目标及并列规则、硬约束、假设、评价器、参数范围与停止条件。先做手算/解析小例和基线，再运行正式求解；保留探索中改变定义的真实时点。优化器输出必须通过独立可行性与目标复算；代理指标只用于筛选。对排名/准入、资源服务链、不同样本比较或最优/必要性声明，读 [decision-contracts.md](decision-contracts.md)：检查操作化口径、硬门槛与条件方案、完整时间链、共同输入，并验证化简保留所声明的全部目标。随机方法报告重复运行波动，离散或连续近似检查分辨率误差。
5. **验证与冻结。** 对照原题逐问检查实质答案与产物，区分实现正确、模型适用、实证预测和决策稳健四类证据。选择能推翻当前推荐的测试，检查基线比较、敏感性、结构假设、情景变化、外推和失败案例。复算应改变一条错误传播路径。结果证书绑定输入、模型、评价器、代码、配置、输出、运行与验证证据。写清“固定策略数值”“预算内最好”“上下界”“证明的最优”分别针对什么声明；求解器的证明只适用于给定数学模型。详见 [validation-review.md](validation-review.md)。

## 论文、评审与修改

按题目要求组织“问题 → 假设与理由 → 数学定义 → 求解 → 结果 → 验证 → 决策”。各问相互依赖时呈现统一主线。方法与结果先写，最后写独立可读的一页英文 Summary Sheet；摘要给出核心选择、关键结果、验证和实际建议。

每个重要数字和图表绑定当前结果证书；引用同时核对 DOI/标题与支撑内容。可获取全文并完成方法/结果/限制阅读后，才引用具体方法或定量结论；仅摘要阅读的文献提供检索线索与明确范围内的概述。231篇学习文献按100篇正刊主库、原80篇子刊扩展、新增49篇子刊研究与2篇方法评论组织，不是每份报告的必引清单。

执行本地两轮评审：先检查要求覆盖、数学正确性、数据、可行性与证据；再检查综合分析、结果解释、适用范围、摘要、决策建议与可读性。每条意见附准确位置、证据、影响、最小修复和复验条件。数学或评价器错误返回求解阶段；文字、引用、公式、图表错误返回论文阶段；排版在交付阶段修复。新证据使相关下游通过记录失效。内部评审与评分规则须标为本地工具。详见 [paper-and-style.md](paper-and-style.md)。

## 自然文风终审

技术内容稳定后，一次整合使用 academic-humanization、humanizer、stop-slop、anti-defensive-writing、no-negative-echo、humanize 的规则。先冻结公式、符号、数字、单位、引文、术语、比较方向、假设与不确定性，再审结构、空话、重复、机械转折、夸大、过度防御和聊天痕迹。

以自然、清楚的英文解释数学，保留准确的专业术语、必要被动语态、真实局限与限定语。让每段承担一个论证任务。编辑后检查保护项与科学语义；文风修改不创造实验、改变最优性或删除真实 AI 披露。详见 [paper-and-style.md](paper-and-style.md)。

```bash
python /path/to/himcm-modeling/scripts/prose_guard.py before.md after.md
python /path/to/himcm-modeling/scripts/audit_project.py PROJECT_DIR
python /path/to/himcm-modeling/scripts/check_pdf.py final/TEAM.pdf --team TEAM --main-pages MAIN_PAGE_COUNT
```

运行环境：初始化、证据审计和文风保护使用 Python 3.9+ 标准库；PDF 检查另需 PyMuPDF。先使用现有运行环境。缺少 PDF 依赖时记录该检查缺口，并通过实际 PDF 阅读完成可执行的复核。

这些脚本提供机械检查，不能证明模型正确、文章匿名或文风自然。`STRUCTURE_PASS` 仅说明已登记的要求和文件绑定符合结构，不检查必需产物是否齐全。交付时另外核对结果证书、输入/模型/评价器/结果/验证证据、可编辑稿、最终 PDF、审阅记录及真实 AI 台账；缺项保留待完成状态。阅读实际 PDF，逐页检查公式、图表、字号、分页与匿名性；绑定最终 PDF 的哈希。截止前冻结所有内容，截止后只执行规则允许的提交动作。

## 交付与学习

交付英文 PDF、可编辑稿、本地代码/数据与结果证书、引用账本、图表源码、审阅记录、真实 AI 使用报告和简短复现说明。提交包按当届规则组织。内部支持 ZIP 与比赛提交文件分开。

完成状态必须说明已执行验证、未解决限制和访问/渲染缺口。需要复盘时，从真实决策、失败和证据提炼下次可执行的改进。复杂或大幅修订的技能用独立新上下文前向测试：评估者只接收冻结技能、完整原题和附件，独立生成构思、数据处理、计算、报告与返修；根审阅者从原输入用替代路径核验核心结果和全部要求。保留初次失败和修复证据，重跑受影响链。历史题资料可能与学习库重叠，记录这一边界；题目数量、格式通过和本地质量检查均不证明官方奖项。来源整合与适配边界见 [source-integration.md](source-integration.md)，100 份来源文档清点见 [source-skill-inventory.json](source-skill-inventory.json)。本机相关技能的具体长处与适配见 [local-skill-learning.md](local-skill-learning.md)。技能结构与脚本验证不等于跨题效果或奖项验证。
